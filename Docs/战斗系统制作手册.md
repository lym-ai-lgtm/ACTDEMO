# ACTDEMO 功能复现手册

整理日期：2026-11-23。UE 5.8 / Windows / C++、蓝图、GAS、Enhanced Input。

本手册按功能组织，只保留当前方案。旧方案、修复过程和逐次验收已完整归档到[历史记录](战斗系统制作手册_历史记录_2026-11-23.md)。本文用于在现有源码和素材基础上重建蓝图配置，不替代源码；蒙太奇通知时间、伤害、蓄力时长以资产最终设置为准。已完成单机演示与打包测试，不代表完成多人同步。

## 1. 制作顺序与职责

依次完成：GAS角色与属性 → 移动与装备 → 单段攻击与伤害 → 连段 → 受击与死亡 → 翻滚、锁定 → 地面/空中技能 → 太刀与变招 → 防御气势 → 敌人AI → HUD → 菜单训练场 → 打包。

| 模块 | 当前入口 |
|---|---|
| ASC、初始化与属性查询 | `Source/ACTDEMO/GAS/ACTDEMOGASCharacter.h/.cpp` |
| 生命、气势、伤害约束 | `GAS/ActDemoAttributeSet.h/.cpp` |
| 敌人授予能力、招架恢复、击飞落地 | `GAS/ACTDEMOEnemyCharacter.h/.cpp` |
| 剑与空中攻击 | `GAS/Abilities/` |
| 太刀基础类 | `GAS/Katana/` |
| 锁定、镜头、悬停、缓冲 | `Source/ACTDEMO/Combat/` |
| HUD数据接口 | `Source/ACTDEMO/UI/` |
| 训练地图、生成服务 | `Source/ACTDEMO/Training/` |
| 玩家输入、装备与蓝图函数 | `/Game/Demo/GAS/BP_GASPlayer` |

上表的 `GAS/` 相对 `Source/ACTDEMO/`；下文 `/Game/` 是UE资产路径，对应项目 `Content/`。

分工：C++提供属性、能力接口、公共规则、物理和查询；UMG/AnimBP/能力蓝图配置动画、交互和表现。现有剑轻击与翻滚保留早期原生任务实现；太刀攻击主要在蓝图中编排，不能假设所有能力实现相同。新增反射接口后由用户完整编译并重启，随后再配置蓝图，不自动重启编辑器。

## 2. GAS、生命值、气势与伤害

### 基础搭建

1. Build.cs启用GameplayAbilities、GameplayTags、GameplayTasks、UMG等现有依赖。GAS角色实现IAbilitySystemInterface，构造时用CreateDefaultSubobject创建ASC和AttributeSet，BeginPlay初始化ActorInfo。
2. 在玩家/敌人蓝图设置初始最大值与当前值，先设置Max再设置Current。属性集负责钳制生命、气势等数值。
3. 配置初始能力数组，服务端GiveAbility授予；输入或AI用TryActivateAbility激活。修改数组后重新生成实例，旧实例不会自动增删能力。
4. 创建瞬时伤害GE，攻击者MakeEffectContext → MakeOutgoingSpec → ApplyGameplayEffectSpecToTarget。上下文记录攻击者与命中信息，便于方向防御和反馈。

### 统一结算规则

`实际命中 → 无敌检查 → 倒地/防御方向检查 → 气势或生命结算 → 受击/破防/死亡事件`。

- 无敌标签 `State.Combat.Invulnerable` 存在时不扣血。
- 敌人可防御、未破防且攻击来自正面180°时优先扣气势；背后命中直接扣血。
- 在敌人蓝图的 `IsAttackInGuardArc` 中：敌人Forward与“敌人指向攻击者”的水平单位向量点积，非负为正面。零距离等退化情况应保持确定规则。
- 敌人气势未归零时，2秒未受攻击开始恢复；归零后用独立破防状态标记持续恢复到满，不能因气势恢复到正数就提前重新防御。
- 倒地恢复状态 `State.Combat.GroundRecovery` 下直接扣血，不重启普通受击、不再次挑飞；致死仍优先死亡。

知识点：GA管行为生命周期，GE管效果与冷却，ASC管授予/标签/生效效果，AttributeSet管属性及约束。伤害前后生命差用于识别实际扣血，不把挥空或成功防御当作血量命中。

复现检查：正面扣气势、背面扣血、倒地扣血不打断、无敌不扣血；破防恢复过程不阻止正常AI移动。

## 3. 移动混合空间、装备与翻滚

### 移动

- 玩家：`/Game/Characters/Mannequins/Anims/Unarmed/ABP_Unarmed`；敌人使用独立 `ABP_MeleeEnemy`，不依赖玩家专用PlayerRef。
- AnimBP更新平面速度GroundSpeed与相对Actor朝向的Direction；二维混合空间Direction范围-180～180°，Speed按实际移动速度配置。前0°、右90°、左-90°、后±180°。
- Idle和移动状态都按装备状态选择姿态；混合空间引脚必须显式连接，不会自动读取同名变量。
- 太刀待机用 `GhostSamurai_APose_Idle`，Walk/Run素材在 `/Game/GhostSamurai/Katana/Apose/Movement/`；已按走300、跑600cm/s校准采样点。
- 敌人大剑素材在 `/Game/Animations/Sword`，实际移动资产在 `/Game/Demo/GAS/Enemies/Greatsword/Movement`。完整跑步序列拆成起跑、持续循环、收步，持续移动只循环中段，不能整段循环起停动作。

### 装备

1. 创建剑与太刀武器蓝图，武器碰撞关闭。骨骼配置手持、背部与腰部插槽；未装备时剑在背后、太刀在腰间，太刀刀鞘单独保留。
2. `1`控制剑拔收、`2`控制太刀拔收；普通装备流程须先收回当前武器才能换另一把。
3. 装备能力播放拔收刀蒙太奇，通知在正确帧切换附着点，再更新装备状态、步态与HUD。
4. 拔收刀期间清掉惯性并限制移动，结束/取消配对恢复。声音使用KatanaEquip、KatanaUnquip、SwordEquip、SwordUnequip。

### 翻滚与无敌

- Shift短按翻滚、长按跑步；翻滚方向按输入相对角色朝向选择。
- 太刀使用八向Slide素材；徒手/剑左右用rise_left_roll、rise_right_roll，其余方向用Rolling。
- 翻滚能力可取消攻击，攻击不能反向抢占翻滚。蒙太奇加入 `ANS_DodgeInvulnerability` 标定无敌区间，开始加标签、结束移除；能力取消也清理。
- 有位移的动画须正确启用根运动与AnimBP根运动模式，不能同时再叠加重复代码位移。翻滚不消耗体力。

检查：走跑脚步与速度匹配、拔收刀不滑行、八向翻滚方向正确、翻滚取消后无敌标签不残留。

## 4. 攻击制作：命中、方向与通知

所有新攻击都按下列步骤制作，再复用到连段和技能：

1. 选兼容骨骼的动画，创建蒙太奇并接入AnimBP全身Slot。根据设计决定原地或根运动；不要为锁原地而误删姿态起伏。
2. 在GA配置蒙太奇、伤害GE、距离/半径和事件标签；蓝图使用PlayMontageAndWait，Completed/Interrupted/Cancelled均接统一结束清理。
3. 蒙太奇在刀刃接触目标帧放命中AN。AN向Owner发送GameplayEvent，GA先注册监听再播放动画。
4. 命中回调执行球形扫掠/范围查询，对同一目标去重，再用GE结算。监听多段命中时不要勾OnlyTriggerOnce。
5. 每段起手调用 `ActDemoAttackFacing::FaceLockedTarget`：锁定则回正到目标，未锁定保持角色朝向。攻击期间限制移动输入，结束/打断配对恢复。
6. 使用 `ANS_BlockMovement` 标记禁止移动区间，`ANS_MontageRate` 标记加速区间；通知状态结束时恢复速率。每个通知实例可设不同倍率，不需复制整个类。

| 攻击 | 命中通知/主要入口 |
|---|---|
| 剑轻击、地面重击 | `AN_LightAttackHit`、`AN_GroundHeavyHit`；`ActDemoLightAttackAbility` |
| 空中轻、重攻击 | `AN_AirAttackHit`、`AN_AirHeavyHit`；独立AirAttack/AirHeavyAttack类 |
| 下砸、E、T、Q | `AN_AirSlamHit`、`AN_AirSlashHit`、`AN_GuardBreakHit`、`AN_FinisherHit` |
| 敌人大剑 | `AN_EnemyMeleeHit`，由攻击能力蓝图执行检测 |
| 太刀 | 对应GA的命中事件回调，蒙太奇通知发送其配置标签 |

所有检测的DrawDebugType/EDrawDebugTrace保持None；关闭的是可视化，不是碰撞检测。录制版本已检查全部原生攻击及相关蓝图轨迹。

知识点：AN适合单次事件，ANS适合持续区间；蒙太奇时钟随播放速度变化，通知比固定Delay更适合命中和连招时机。任务结束回调可能重入，不能再EndTask已经销毁的任务。

## 5. 连段、轻重变招与输入缓冲

### 通用连段流程

`激活 → 当前段索引初始化 → 注册输入/命中/衔接事件 → 播放当前段 → 缓存输入 → 通知开放窗口 → 检查缓存并推进 → 结束清理`。

- 输入只登记请求，通知决定何时切段；不是等整段播完才允许衔接。
- 未命中也允许变招。超时或能力结束清掉段数、缓存和临时标签。
- 同一段可用命中去重防止重复结算；需要多刀时，按通知重新开放本刀检测，不能整套永久去重。
- 剑地面轻3、重3；空中轻3、重4，分别独立能力。剑地面轻重衔接也由通知开放。

### 太刀

文件：`GAS/Katana/ActDemoKatanaLightAttackAbility.h/.cpp` 提供基础配置；`/Game/Demo/GAS/Katana/Abilities/GA_KatanaLightAttack`、`GA_KatanaHeavyAttack` 编排流程。

1. 蒙太奇数组按轻1～6、重1～4排序；输入发给当前能力缓存。
2. 采用各GA配置的ComboChainEventTag，时间轴发同一标签；把通知放到允许衔接的位置。
3. 1秒没有后续输入则重置首段。允许路线：轻1→轻2→重3→重4；轻1→重2→重3→轻6。
4. 跨能力用 `State.Combat.Katana.Combo.Active/Heavy2/Heavy3/Light6` 临时标签交接段数；新能力消费后清除，激活失败也清理。
5. 重3两次挥刀分别结算，重4环形多段检测覆盖周身。太刀R环形末段也独立多次命中。

蓝图定位函数/事件：QueueKatanaSameInput、QueueKatanaMixedInput、OpenKatanaChainWindow、PlayCurrentStage相关播放区、ProcessKatanaHit、FinishKatanaCombo。按模块注释区阅读，不跨图拉长线。

### 跨动作输入缓冲

`Combat/ActDemoCombatInputBufferComponent`用于收招末尾缓存待执行动作，区别于“当前攻击内部的下一段请求”。先让活动连段消费输入，未消费才交通用缓冲；否则同一次点击可能同时续段和启动新能力。动作结束后再次检查状态再执行，避免死亡/受击时执行过期请求。

检查：纯轻/纯重、两条变招、通知前预输入、超时重置、挥空变招、受击/翻滚取消后重新起手。

### 击飞、追击、悬停与落地

1. 对存活敌人施加向上/水平速度，添加Airborne状态并发送 `Event.Combat.Launch.HitReact`，由GA_LaunchReact播放击飞反应。
2. R追击使用Attack_Jump_to_Air；空中轻击Air_Attack01～03_Z0，重击04～07_Z0，F用Air_Down_Attack_Z0。
3. `ActDemoAirSuspensionComponent`在实际扣血后SuspendFor刷新悬停，保存原GravityScale，释放时恢复。挥空/起手不刷新目标；计时到期自然下落。
4. 空中受击用hit_air01。普通空中轻3不再自动击落；击落由F承担。
5. 落地事件驱动倒地hit_down_idle_up与起身rise_2，不用固定Delay猜测着地。倒地至起身保持正确姿态，避免闪回Idle。
6. 末段接F的延长窗口沿用悬停接口，只在允许衔接时适度延长，不改全局重力。

### Q与T的当前表现

- 剑Q使用 `A_Finisher03_Z0_InPlace` 的原始根运动节奏，已修正起手高度；不采用匀速前推。普通命中逐刀结算并刷新悬停；最后一个AN_FinisherHit勾FinalUppercut，发送独立LaunchHit事件。不要把每个通知都设为最终上挑。
- `ActDemoAbilityTask_FinisherFollow`在实际命中后保持敌人位于身前刀程内；使用首次命中的固定方向/高度关系，不追踪受击胸骨。末段、悬停到期、死亡、脱离距离或打断结束跟随。参数在GA_Finisher的Target Follow与Final Uppercut分类。
- Q起手右绕40°，末段通知回正；`State.Combat.FinisherCamera` 在绕镜与回正期间阻止锁定蓝图写相机控制角，回正完成再移除，避免反馈晃动。
- T在约18/35帧放刀光，45帧放脚下震荡波与环形灰尘。特效NS_GuardBreakShockwave、NS_GuardBreakDustRing；不要将表现通知误当命中通知。

- 太刀Q蓄力动作与释放段分开，释放不重复向后迈步；以最终资产的蓄力时长和播放倍率为准，不照抄历史1.5/2秒试验值。

## 7. 武器切换特殊攻击

入口X；锁定目标向右切换已改为C，避免按键冲突。

1. 创建切换GA，按当前装备选择剑→太刀或太刀→剑。剑→太刀使用GhostSamurai_APose_SPAttack02_Root_Montage，太刀→剑使用AM_AirSlash。
2. 动画通知在实际换手帧切换附着点和装备状态，再更新步态及技能输入路由，不能只换模型而保留旧能力入口。
3. 共用3秒冷却；右侧HUD显示当前与待切换武器，显示剩余冷却。
4. 保留普通1/2拔收刀限制；特殊X是战斗中切换的独立入口。

检查：两个方向动作、命中、装备状态、技能栏和共用冷却一致；持太刀E不得误放剑E。

## 8. 防御、精防、破防与受击死亡

### 太刀防御与精防

1. E按下进入太刀防御，松开结束。使用DefenseR姿态和八向防御混合空间，状态机按速度选择静止/移动；不再使用已移除的旧Tab剑防御。
2. 记录防御起手的短暂精防窗口，命中时检查普通防御/精防。普通格挡消耗自身气势，精防不耗自身气势并削减攻击者气势。
3. 气势耗尽进入GA_PlayerKatanaGuardBroken，播放GhostSamurai_DefenseR_Broken_Root对应蒙太奇；恢复逻辑由现有气势规则驱动。
4. 正常格挡/精防分别使用AM_Defence_Hit02_Player、AM_Defence_Hit02_Perfect，火花大小不同。

### 敌人招架与反馈

敌人正面招架、背面掉血和倒地保护统一见第2节。招架播放AM_EnemyParry，剑身三点火花使用NS_EnemyParrySparks，破防闪光使用NS_EnemyPostureBreakFlash及Edge资产。

### 受击与死亡

- 角色必须授予GA_HitReact、GA_Death及所需击飞反应；事件标签与能力触发标签一致。
- 生命归零立即写Dead、取消其他能力、停AI，动画完成后销毁。Dead状态不随死亡GA结束而移除。
- 空中致死：释放悬停，保留下落能力，不立即DisableMovement；无Controller仍允许运动物理。Landed发送 `Event.Combat.EnemyDeath.Landed`，GA_Death等到该事件才播放死亡蒙太奇。地面致死直接播放。
- 死亡落地不进入存活倒地/起身流程；动画末尾保持死亡姿态，避免销毁前站回Idle。

检查：普通格挡、精防、气势耗尽、恢复、背击、倒地受击、空中/地面死亡；确认敌人死后不能继续造成伤害。

## 9. HUD、血条与冷却制作

### 生命与气势条

1. `/Game/Demo/GAS/UI/WBP_PlayerHealth`、WBP_EnemyHealth派生 `UActDemoHealthWidget`。UMG放ProgressBar，保留 `HealthBar`、`PostureBar` 控件名；HealthText可选，不需要数字则隐藏/移除。
2. `ActDemoHealthDisplayComponent`配置HealthWidgetClass并传入属性来源；玩家HUD加到视口，敌人通过WidgetComponent挂在头顶。
3. 进度=当前/最大，防止最大值为0；C++读取/更新，设计器调整大小、颜色、内边距。要填满框体，检查Border/Slot Padding和ProgressBar样式边距，而非仅放大整个控件。
4. 敌人受伤或被锁定才显示血条；显示时长在HealthDisplay组件调，默认3秒。气势变化也需要刷新显示。

### 技能栏与冷却

1. 使用 `ActDemoSkillCooldownWidget` 和WBP_ECooldown、WBP_TCooldown等子控件；技能释放时GA提交冷却GE，GE持续时间/标签由ASC管理。
2. 查询ASC的生效冷却，更新剩余秒数、遮罩/暗淡状态；结束恢复亮度，不自行再跑一个与GE不同步的固定Delay。
3. 根据装备状态显示剑或太刀技能；Q蓄力进度来自技能蓄力状态，不是生命AttributeSet。
4. UI布局保持UMG可编辑，新增控件名与BindWidget接口一致，否则代码找不到而界面仍能编译。

知识点：UI显示数据，不能决定伤害和冷却是否生效；先保证GE/属性正确，再查绑定和控件可见性。

## 11. 锁定、朝向与镜头

1. `ActDemoLockOnComponent`负责搜索、切目标、距离/存活检查；OnLockTargetChanged将目标写入玩家蓝图，更新标记与输入。
2. 锁定时镜头看向目标并插值，角色朝向按统一函数处理；攻击/翻滚等状态不能被普通移动旋转抢占。解除锁定恢复对应武器的旋转模式。
3. `ActDemoLockCameraBoom`保留弹簧臂碰撞；目标高于玩家时拉远并抬高，限制近身时的仰角，避免镜头绕到角色下方。
4. Q绕镜参数在CameraBoom > Q Orbit：右40°、转入120°/秒、回正180°/秒；使用相机互斥标签避免锁定反算相机位置造成反馈。
5. 训练场锁定隐藏鼠标、GameOnly；解除后GameAndUI恢复鼠标。拖放期间保留UI交互，结束按锁定状态恢复。

检查：目标靠近、高低差、死亡/销毁、切目标、Q整段及回正；不能只检查静止目标。

## 12. 音效、特效与震动

1. 命中肉体：Hit1～Hit5组成Sound Cue随机节点，每次实际命中播放一个。环形多段攻击的声音随每次命中触发，避免整套只响一次。
2. 刀光、火花、血花通过现有蒙太奇AN/ANS或命中回调触发；视觉特效不承担伤害判定。血花喷出点在上胸，注意方向、缩放与材质侵蚀参数。

## 14. 打包、保存与最小验收

### 保存与构建

- 新C++类/属性/函数：用户完整编译、重启后再重设蓝图父类/引用。不要把编译Editor成功等同于Cook成功。
